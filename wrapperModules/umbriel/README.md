# Umbriel adapter

[umbriel.nix](umbriel.nix) exposes `settings` and `configDir`. The directory
defaults to `${XDG_CONFIG_HOME}/umbriel`, and `sync.defaultDir` follows it inside
the adapter. `constructFiles.umbrielConfig` maps directly to native `config.toml`.

Sync merges the saved snapshot, then explicit settings, into that writable file.
Declared values win conflicts; runtime-only keys survive. Arrays replace whole.
Automatic sync runs before compositor launches (no arguments, `-s`, or `-c`);
IPC, inspection, help and configuration validation do not overwrite runtime edits.
`umbriel-sync` reapplies the baseline manually. `umbriel config validate` checks
the selected runtime file, so run sync first in a fresh profile. The wrapper
keeps subcommands first and safely expands/quotes HOME/XDG paths.

The adapter passes `-c` to select its writable config, which Umbriel watches and
reloads natively. Choose `configDir` to relocate launch, sync and snapshot together.
An explicit CLI `-c` can inspect/run a different file, but does not retarget sync
or snapshot. No systemd sync unit, `/etc` config, custom watcher or rebuild hook
is supplied. After a rebuild, use the new package's `umbriel-sync` or start a new
session to apply its baseline. Environment/autostart/DRM changes still require a
new compositor session.

`umbriel-snapshot` captures `config.toml` without starting or syncing the app.
It retains layout, appearance, keybindings and portable rules. It removes
includes, environment wiring, DRM/output/device settings, output selectors,
credential-like keys and store paths. Those integration values belong in Nix.
Pruning inside arrays removes the whole array; empty tables are cleaned up.
Native included files (such as Noctalia-generated colors) remain live inputs to
Umbriel but are not flattened into the exported master baseline.

## Validation and snapshot review

[Adapter checks](checks/check.nix) use independent preferences, real native
configuration validation, and synthetic runtime edits to verify merge, pruning,
capture and fresh-profile restoration. A fake compositor executable checks
launch arguments and IPC isolation. A separate check compiles the pinned native
file watcher and verifies repeated atomic replacements, matching sync-snap writes.
The fixture export is compared with the exact expected portable preferences,
then validated by the real application after restoration.

The feature retains the GTK theme-loader, Qt plugin and Noctalia template
integration checks. These checks do not launch a compositor desktop: the prior
headless compositor attempt lacked a buffer allocator device in the build sandbox.
Live GUI/layout validation remains separate from native config/watcher checks.

Reference: [Umbriel configuration](https://docs.noctalia.dev/umbriel/configuration/).
The pinned source includes `docs/user/configuration.md` and the reload contract
in `docs/design/configuration-reload.md`.

The configured feature's manual snapshot command was run against an isolated
profile and reviewed. The retained baseline contains layout preferences and
portable keybindings. Packaged launch commands, theme environment and include
paths were excluded and are regenerated by the feature. Native validation and
the GTK/Qt integration checks passed.
