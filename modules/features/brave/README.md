# Brave

`mybrave` installs Bitwarden through Home Manager, recommends Google search, and
keeps writable preferences with password saving and automatic sign-in disabled.

## Personal configuration

Everything you normally edit is in **[config/](config/)**:

| File | Purpose |
| --- | --- |
| [default.nix](config/default.nix) | Extensions, browser flags, explicit preferences, sync policy, snapshot filters |
| [recommended/defaults.json](config/recommended/defaults.json) | Google and password-manager policy recommendations |
| [snapshot.json](config/snapshot.json) | Captured GUI baseline; generated by the snapshot command |
| [snapshot-pruning.json](config/snapshot-pruning.json) | Preference paths to exclude from snapshots |

For example, inside `default.nix`:

```nix
settings.bookmark_bar.show_on_all_tabs = true;
homeManager.programs.brave.commandLineArgs = ["--no-default-browser-check"];
syncSnap.sync.preferences.policy = lib.mkDefault "fill-missing";
```

Edit the existing policy assignment when changing it. `merge` reapplies declared
values on every cold launch; `fill-missing` preserves existing GUI values.
Snapshot values are layered first, explicit `settings` second. Runtime-only keys
survive both policies. Arrays are whole values. `syncSnap.enableSync` and
`syncSnap.enableSnapshot` independently disable either facility.

## Run and capture

```sh
nix run path:.#mybrave
# Close Brave normally so its preferences are flushed, then:
nix run path:.#mybrave-snapshot -- "$PWD/modules/features/brave/config/snapshot.json"
git diff -- modules/features/brave/config/snapshot.json
# Rebuild/relaunch to embed the reviewed snapshot:
nix run path:.#mybrave
```

Use `path:.` while files are untracked. Installed packages also provide
`brave-sync` and `brave-snapshot`; the flake exposes `mybrave-sync` for manual
baseline adoption. Exporting does not rebuild, commit, or reload the browser.
The optional NixOS feature sets `syncSnap.snapshotFile` to the checkout snapshot
and supplies live recommended policies. It is not enabled on any host here.

The default profile is `${XDG_CONFIG_HOME:-$HOME/.config}/mybrave/Default`.
All three commands accept `--user-data-dir` and `--profile-directory`, with either
`--flag=value` or `--flag value` syntax. For example:

```sh
nix run path:.#mybrave-snapshot -- /tmp/brave.json \
  --user-data-dir /tmp/brave-trial --profile-directory 'Profile 2'
```

Set `userDataDir`/`profileDirectory` for permanent defaults. Do not put these
flags in HM `commandLineArgs`: the sync target must be known before HM's launcher.

## Behavior to know

- Startup sync fails open: errors produce diagnostics but Brave still launches.
  Manual sync returns failure. Invalid input prevents publication of all sync
  outputs for the program; publication is atomic per file, not a multi-file rollback.
- An existing `SingletonLock` skips automatic sync and refuses manual sync.
  Sync-snap additionally serializes its own operations and checks source/runtime
  hashes. The marker is a best-effort guard; concurrent first launches still have
  a gap before Brave takes ownership. Never remove a real running browser's lock.
- Snapshots read only `Preferences` on disk. Missing/invalid input preserves the
  previous snapshot and writes a sidecar error log. Close Brave before capture.
  Account, extension, protected, and runtime fields are filtered; inspect the
  output and extend the denylist as needed. Matches inside arrays drop the whole
  array. `syncSnap.snapshot.preferences.transform` accepts additional jq filters.
- Google is a recommended policy: a GUI search choice can override it. Protected
  search preferences are not exported. Live policy edits can be reloaded at
  `brave://policy`; externally edited Preferences do not reliably hot reload.
- Sign into Bitwarden and accept **Make Bitwarden your default password manager →
  Allow**. That [interactive permission](https://bitwarden.com/help/disable-browser-autofill/)
  is still required. HM's external manifest allows browser-managed installation
  and updates; an extension removed in the GUI may need manual reinstallation.
- HM integration directories are copied as overlays. Removing a declaration does
  not delete an old runtime manifest; remove obsolete files after closing Brave.

## Implementation and checks

[brave.nix](brave.nix) only handles host integration and flake commands.
The [Brave adapter](../../../lib/wrappers/brave.nix) reuses the pinned HM
`programs.brave` module for its final package, extensions, dictionaries, and native
messaging hosts, without HM activation. HM exposes no native preferences or
recommended-policy option, so those use `settings` and `configDir`.
Brave's fixed `/etc/brave/policies` path is supplied privately through `buildFHSEnv`;
Linux namespaces are required, and the browser may show a managed-policy indicator.

The [shared sync/snapshot module](../../../lib/wrappers/README.md) owns helper
commands and startup wiring. App tests live in [tests/wrappers/brave](../../../tests/wrappers/brave/),
with a separate non-browser test for the shared module:

```sh
nix build path:.#checks.x86_64-linux.mybrave-sync-snap \
  path:.#checks.x86_64-linux.wrapper-sync-snap --no-link
```

These checks use disposable files and a simulated launcher. They cover HM
extraction, profile arguments, baseline round trips, pruning, failure behavior,
and locks. Real headless validation separately exercised Google, Bitwarden
installation, writable preferences, and restart behavior. Headless shutdown
required forced process-group cleanup in its disposable profile; ordinary GUI
shutdown and interactive Bitwarden login/autofill remain manual checks.
